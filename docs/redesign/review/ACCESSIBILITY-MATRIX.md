Programmatic focus was used only to attempt focusing the inert background and verify modal isolation. These are automated key events, not an observed keyboard-user session.

All three engines also ran the existing 40 frozen search queries, eight short activities, saving eight responses, journey resume/filter behavior, and verification of eight activity PDF responses. ## Real browser zoom

The [rHbF6DFC zoom receipt](../../../output/accessibility-2026-11-05/recheck-rHbF6DFC/browser-zoom.json) records real managed Chromium browser zoom, independently of the viewport matrix. A task-owned Manifest V3 extension called [`chrome.tabs.setZoom` and `getZoom`](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-setZoom) in an isolated [persistent Chromium context](https://playwright.dev/docs/chrome-extensions). The profile and extension were removed after closing the browser. No installed Chrome profile or user browser was used.

| Requested/reported zoom | Fixed outer viewport | Measured CSS viewport | Device-pixel ratio | Visual viewport scale |
| ----------------------- | -------------------- | --------------------- | ------------------ | --------------------- |
| 100%                    | 1280×900             | 1280×900              | 1                  | 1                     |
| 200%                    | 1280×900             | 640×450               | 2                  | 1                     |
| 400%                    | 1280×900             | 320×225               | 4                  | 1                     |

Home, investigations, Nalanda reading and notebook passed horizontal-reflow checks at all three zoom settings in both themes (24 route measurements). Glossary, image inspection, search and saving a question worked at each zoom/theme setting, with all four dialog bounds inside the available CSS viewport (24 dialog checks). Vertical scrolling remains necessary, especially at 400%. Native Firefox/WebKit zoom and an evaluator's configured browser zoom remain pending; their 320-pixel viewport cases are responsive-layout evidence only.

Zoom screenshots use direct Chromium `Page.captureScreenshot` compositor capture. The initial Playwright screenshot helper returned blank pixels at 400% with a nonzero document scroll position despite normal layout and usable controls. A same-position compositor capture showed the expected enlarged content; the final capture method retains real browser zoom and avoids that CSS-clip artifact. An initial Firefox `img.decode()` timing rejection was resolved in the test harness by awaiting image completion and positive natural dimensions before decoding. Awaiting decode also corrected a narrow WebKit screenshot captured before image paint. Neither diagnostic required a product change. Final screenshots include search feedback scrolled into view at 400%; the enlarged dialog uses vertical scrolling without horizontal overflow.
