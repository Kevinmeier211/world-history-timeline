# Print catalog and short activity packets

Eight two-page US Letter packets accompany the chapter learning contracts. The investigation page shows page counts and download sizes. All eight are below 1 MB, within the plan's 2 MB short-sheet target.

Each contains the selected question and activity, the required image or text evidence, space for an initial explanation, relevant source notes, facilitator guidance, a revisit prompt, source links and image credits. The activities reuse the existing dossier material. This pass checks selection, citation inclusion and layout; it is not a new independent historical review. Durations remain estimates awaiting readers.

Generate with `python3 scripts/completion/activity-pdfs.py` inside the resource launcher. Runtime inputs are the canonical corpus, `src/atlas/chapter-learning.json`, local media, Python ReportLab/Pillow/pypdf, Node Sharp, and the macOS Georgia regular/bold font files explicitly named in the script. Raster photographs receive print-only JPEG derivatives (maximum 1200 pixels, quality 90); SVG diagrams receive PNG derivatives. Original application image files remain unchanged. Review fine details at intended print size before physical-print acceptance.

The generator writes to `output/pdf/chronos-short-activities/`, checks US Letter geometry, nonblank extracted text, required evidence/source headings and size limits, and emits a SHA-256 manifest. Render all changed pages with Poppler and inspect them before copying the PDFs into `public/atlas/exports/` and updating `src/atlas/short-print-index.json` with their exact byte counts/hashes. That copy/update is deliberate: regeneration alone must not silently publish an unreviewed PDF into the application catalog.

The November 4 candidate has sixteen rendered/inspected pages. Extra-page layout defects were removed. The Nimrud source introduction was scoped to the selected excerpt; the Byzantium facilitator paragraph retains its separate ship-repair source. Those affected pages were re-rendered and checked. Browser checks verify the exact served bytes for every short PDF in Chromium, Firefox and WebKit.

Remaining gates: physical printer review; reader comprehension/timing; independent historical review; and PDF accessibility/tagging review. The current ReportLab outputs are not presented as tagged accessible PDFs. The web activities remain the interactive reading alternative. The full catalog now contains 77 dossier readers, eight chapter bundles, 33 family sheets, eight short packets and four complete collections. Individual readers are below 5 MB, chapter bundles below 10 MB and family/short sheets below 2 MB. The optional complete chapter collection is approximately 16.66 MB; the complete family collection is approximately 10.74 MB. All 130 served PDFs have been checksum-verified. Browser-rendered PDFs use tagged output, but reading order/PDF accessibility acceptance remains open.

## Reproduce the wider catalog

Generate print-only derivatives with `node scripts/completion/print-derivatives.mjs`; preserve the source images. Build the candidate and serve its exact directory on a loopback port. Run `ATLAS_URL=<origin> ATLAS_BUILD_ROOT=<candidate> node scripts/completion/export-catalog.mjs` inside the heavy-job launcher. The exporter uses managed Chromium, checks nonblank text/paper/page counts/size budgets, writes hashes and copies exact files plus catalog into the candidate. Use `--ids <comma-separated-export-IDs>` for reviewed affected outputs. Invalid IDs and catalog failures are checked before launching a browser.

`python3 scripts/completion/review-downloads.py` renders every page and checks text bounds. It accepts `--ids` and `--report-dir` to preserve a baseline receipt while reviewing changed exports. The initial 130-file receipt rendered 1,881 pages with no text outside page bounds. The later four-file editorial batch has its own receipt. Rendering is not visual acceptance: record inspected contact sheets and full-size pages explicitly. Poppler bbox extraction crashes on the eight ReportLab packets in this environment; their bounds use pdfplumber, while every page still renders through Poppler.

`print-content-impact.mjs` compares all 122 browser print routes under old and new corpus inputs. The glossary/citation/spacing batch changed four routes; only those PDFs were regenerated. Each catalog row keeps its actual generation input hash, including unchanged PDFs. The eight short packets do not use the repaired claim or Canandaigua activity fields.
